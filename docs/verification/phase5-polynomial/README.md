## 来源与实现

已读取中文版 PDF 的第8.1、8.7、8.8节及习题8.3，并渲染目视核对长除法图和习题前两题。PDF SHA-256：`aa0b3762c2ea451803e325c695c0d90d3dd02b30d9cf5ab0818464f4bb1dbdae`。未把 PDF 页码放进应用。

外层 `gcd` 函数体与仓库 `配套代码(fm2gpcode)/ch12.h` 完全一致（测试忽略空白比较）。同一循环在正文第8.7节用于欧几里得整环；配套文件中它位于第12章代码，界面明确链接 ch12.h 的实际函数行。长除法标为第8.1节定义的教学展开，首一化标为书中循环返回后的独立后处理。

- 固定在 ℚ[x]，输入为降幂整数系数数组；原始1—9项，每项绝对值≤1000。先校验原始文本与原始项数，再转换。拒绝空白、空数组、遗漏项、小数、指数形式、超长和越界。
- 保留原始系数，只移除标准形的前导零；中间零和末尾零保留幂次。零标准形为 `[0]`。分数采用 BigInt、约分、正分母和0/1；中间分子分母不受输入上限限制。
- 共享已应用输入、两个独立播放器。编辑显示待应用；应用或选择示例后同时停止并复位。无效应用保留草稿并显示对应字段错误。
- 一次消元将 Q、R 成对更新后才增加计数并验证 A=BQ+R。外层完成 swap 才增加 GCD 迭代数。回放、验证、最终首一化不增加这两种计数。
- 快照保存函数、语义事件、代码行、独立外层 a/b 和内层 A/B/Q/R、商项、乘积、返回值、已完成调用和计数。调用期间外层暂停；返回赋值时移除内层作用域，防止辅助变量归属错误。
- GCD 完成返回原始多项式后，独立首一化。零多项式次数明确为未定义；先检查零，再比较次数。gcd(0,0)=0 是本演示约定。零除式只禁用带余除法，GCD 仍可运行。
- 章节8.1/8.7/8.8、习题8.3前两题、首页与章节搜索均接入；第8章有霍纳→带余除法→泛型GCD路线。先修包括霍纳、整数求余；代数结构和系数域提供补充入口。
- 第8.3节仍匹配诺特与抽象代数，习题8.3匹配多项式GCD习题，显式检索分别测试。

## 固定结果与计数

| 示例 | 带余除法 Q | 带余除法 R | GCD原始返回 | 首一GCD | GCD迭代 / 累计消元 |

| 书例：3x³−4x²−6x+10 / (x−2) | 3x²+2x−2 | 6 | 6 | 1 | 2 / 5 |
| (x²+1) / (2x+1) | x/2−1/4 | 5/4 | 5/4 | 1 | 2 / 4 |
| 习题8.3（1） | 1 | 8x³−44x²+46x+35 | −4x²+24x−35 | x²−6x+35/4 | 3 / 5 |
| 习题8.3（2） | 7/11 | −39x³/11−74x²/11−31x/11+4/11 | (605/1521)(x+1)² | x²+2x+1 | 3 / 5 |
| 两个零多项式 | 禁用 | 禁用 | 0 | 0（约定） | 0 / 0 |
| 常数4、6 | 2/3 | 0 | 6 | 1 | 1 / 1 |

书例独立长除法为3次消元：商项依次3x²、2x、−2；余式依次2x²−6x+10、−2x+10、6。显示 A(2)=6 与霍纳的联系。习题第一题的三次求余返回依次为8x³−44x²+46x+35、−4x²+24x−35、0。第二题严格保留原始系数605/1521，到最终返回后才首一化。

完整不可变轨迹见 [key-traces.json](key-traces.json)。其中 BigInt 分子分母在 JSON 中序列化为十进制字符串，未转为浮点数。

## 发现、修复与复测记录

1. 算法先补测试，初始因模块尚不存在失败：[RED](red.txt)。实现后24项初始数学测试通过：[初次GREEN](initial-green.txt)。后续追加组件、独立数学和来源测试，最终全量447项通过。
2. 开发期 TypeScript 检查指出搜索测试误把字符串直接传给 searchAlgorithms；改为真实 `{query,lang}` 参数，再跑针对性及全量测试。避免把未实际执行查询的测试算作有效搜索覆盖。
3. 首次浏览器脚本以“多项式”筛选8.1节链接，同时命中霍纳和新页面，触发严格模式错误：[原日志](browser-first-failure.txt)、[原记录](browser-first-audit.json)。改为精确的 `/polynomial-gcd` 链接。
4. 第二次脚本在初始导航滚动恢复完成前开始定位搜索，视口断言失败：[原日志](browser-second-failure.txt)。复用已有专项的双帧等待与220px定位方式后逐字检查，四组全部通过。未修改滚动恢复实现。
5. 最终补展开笔记的双语/页码检查、精确配套源码比较和实际函数行链接后，重新构建并重跑本轮浏览器专项，刷新本轮截图。既有回归针对相同算法及导航实现运行；最后的源码行链接变化不涉及这些旧页面。

现有 Browserslist 数据更新提醒和 npm 升级提示为非阻断提示；未为本轮新增或升级依赖。没有尚未通过的本轮验收项。验收范围为上述明确场景与桌面 Edge 的390px视口，不声称已覆盖真实手机浏览器全部行为。
